# 中国象棋 · 联机对弈

一个**零第三方依赖**的中国象棋网站：支持联机对战、四种玩法模式、人机对战、本地双人热座，
带有「可被白吃」的红/绿描边提示、吃子特效与绝杀特效。

## 快速开始

```bash
node server/index.js
```

然后浏览器打开 **http://127.0.0.1:3000**（端口可用环境变量 `PORT` 指定，例如 `PORT=8080 node server/index.js`）。

联机玩法：一方「创建房间」拿到 6 位房号 → 另一方在大厅输入房号「加入」→ 双方点「准备」自动开局。
链接带 `?room=XXXXXX` 可直接进房；两个座位坐满后第三人自动成为**旁观者**（只能看，不能走子）。

**不想联机也能玩**：大厅里有「人机对战」（可选难度与先手，离线可用）和「本地双人（热座）」。

### 放到 GitHub Pages 上玩（免费、无需服务器）

仓库根目录带了一个 `index.html` 入口和 `.nojekyll`，**不用改代码**即可托管：

1. 把仓库推到 GitHub；
2. Settings → Pages → Source 选 **Deploy from a branch**，分支 `main`，目录 **`/ (root)`**；
3. 访问 `https://<你的用户名>.github.io/<仓库名>/`。

Pages 上能玩**人机对战**与**本地双人**；**联机不行**（Pages 只托管静态文件、没有 Node 进程，
WebSocket 连不上）——页面会自动识别并给出提示。联机请部署到能跑 Node 的主机，见 [`docs/DEPLOY.md`](docs/DEPLOY.md)。

跑测试：

```bash
npm test
# 等价于 node --test "tests/**/*.test.mjs"
```

## 四种模式

| 模式 | 说明 |
|---|---|
| **正常模式** | 标准中国象棋，双方全明开局。 |
| **揭棋** | 帅/将固定在九宫原位且为明子；本方其余 15 枚身份随机洗牌后**背面朝上**。暗子按它**所在初始格的位置角色**走（在车位移车步、在马位移马步、在炮位移炮步、在兵位只能前进一格）；暗子**一移动就翻开**，之后按真实身份走；暗子被吃时先翻开再移除。**双方都看不到暗子的身份**（包括自己的）。 |
| **全乱揭棋** | 含**将/帅**在内 16 枚身份全部随机洗牌到本方 16 个初始格，全部背面朝上。因为连将/帅在哪都不知道：**将/帅被吃立即判负**；只有**已经翻开的**将/帅才会被将军、才受"不能送将"的约束。 |
| **全明乱棋** | 用户所说的「一开始就揭完的全乱揭棋」：布局与全乱揭棋完全相同，但**开局即全部翻开**，完全按正常象棋规则行棋。 |

完整规则见 [`docs/RULES.md`](docs/RULES.md)，也可以在游戏大厅点「规则说明」。

## 红 / 绿描边（安全吃子提示）

某枚棋子如果**能被对方吃掉、并且对方吃完之后不会被任何棋子反吃**（俗称"白吃"），就会显示描边：

- **红色描边**：这是**我方**的棋子，正被对方白吃 —— 赶紧处理。
- **绿色描边**：这是**对方**的棋子，我可以白吃它。

同一批棋子在双方视角下颜色不同：轮到走棋的一方看到绿色（机会），等待的一方看到红色（危险）。
判定使用引擎的真实局面（含暗子翻开后的真实身份），保证"提示即事实"。

## 特效

- **吃子**：命中白闪 + Canvas 粒子爆散 + 棋盘震动 + WebAudio 合成爆响；被吃的棋子碎裂淡出。
- **绝杀**：全屏"绝杀!"横幅 + 冲击波光环 + 粒子雨 + 棋盘压暗 + 低频轰鸣。困毙显示"困毙!"、吃将显示"擒王!"、认输显示"认输"。
- **将军**：红色脉冲环 + 双音警示 + 顶部"将军!"徽标。
- **翻开**：暗子翻明时的翻牌脉冲 + 音效。
- 所有音效由 WebAudio 实时合成，**不含任何音频文件**；粒子用全屏 Canvas 绘制。

## 目录结构

```

shared/protocol.js   前后端共享的协议常量
server/ws.js         零依赖 RFC6455 WebSocket 实现（握手/掩码/分片/心跳/大小限制）
server/rooms.js      房间与对局会话（权威判定、按座位下发脱敏视图、观战、重连、再来一局）
server/index.js      HTTP 静态服务 + WebSocket 升级 + /health
public/              前端（大厅 / 房间 / 棋盘 / 特效 / WebAudio 音效）
public/js/ai.js      人机对战 AI（迭代加深 + α-β 剪枝；不依赖 DOM，可被测试直接 import）
index.html           仓库根入口：静态托管时重定向到 public/，让 Pages 能直接跑
Dockerfile           容器镜像（零依赖，无需 npm install）
tests/               node:test 测试套件（含独立实现的 WebSocket 客户端做端到端验收）
docs/CONTRACTS.md    接口契约（引擎 API / HTTP / WebSocket 协议）
docs/RULES.md        玩法规则说明
docs/DEPLOY.md       部署指南（GitHub Pages / Docker / 局域网访问 / 手机适配现状）
```

## 设计要点

- **服务器权威**：所有走子都由服务器用同一份 `shared/engine.js` 校验，非法走子返回 `error` 且状态不变。
- **暗子身份保密**：服务器下发给每个座位的都是 `viewFor(state, seat)`，未翻开的暗子 `type` 恒为 `null`；
  旁观者用 `viewFor(state, null)`。**游戏结束后仍未翻开的暗子同样不下发身份**（测试中有专门断言）。
- **同一份引擎**：浏览器直接 `import` `/shared/engine.js` 跑人机与本地双人；服务器 import 同一文件做权威判定，
  规则零分叉。
- **人机 AI**：`public/js/ai.js` 用迭代加深 + α-β 剪枝 + 简单局面评估，按难度设时间上限；
  对未翻开的暗子按「所在初始格的位置角色」估值（这是公开信息），不会因为偷看真实身份而虚高。
- **按需连接**：只有点了「创建房间 / 加入房间」才会去连 WebSocket；静态托管下直接识别并提示，
  不会无限重连。
- **零依赖**：没有 `dependencies`，WebSocket 由 `server/ws.js` 手写实现（RFC6455），
  音效由 WebAudio 合成，测试用 `node:test` + 手写 WebSocket 客户端。

## 已验证

- `node --test "tests/**/*.test.mjs"` → **55 项全部通过**。
- 覆盖：标准开局 44 着基准、马腿/象眼/炮架/过河兵/九宫/飞将/应将/困毙/绝杀、
  四种模式布局与 seed 可复现、暗子按位置角色走且移动即翻开、被吃先翻开再移除、
  安全吃子高亮的正例与「能被吃但会被反吃」负例、红/绿视角映射、
  以及真实启动服务器后用独立 WebSocket 客户端走完整局并断言**暗子身份全程不泄露**。
- 人机 AI：四种模式下都只返回合法着法、不修改输入局面、遵守时间上限、会吃掉白送的子，
  并能自我对弈（含揭棋模式下的连续走子）。
